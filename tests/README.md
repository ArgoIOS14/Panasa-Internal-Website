# Panasa Website Tests

Playwright end-to-end test suite generated by Argo Tester. Tests run against the local PHP dev server, which Playwright boots automatically via the `webServer` fixture in [playwright.config.ts](../playwright.config.ts).

## One-time setup

```bash
npm install
npx playwright install chromium firefox webkit
```

Requires PHP 8+ on `$PATH`. The default Playwright port is `8088`; override with `PORT=9000 npm test` if it clashes.

## Run

```bash
npm test                 # full suite, headless, all 4 projects
npm run test:ui          # interactive Playwright UI runner
npm run test:headed      # visible browser
npm run test:smoke       # route-load smoke only
npm run test:contact     # contact form
npm run test:a11y        # axe accessibility checks
npm run test:report      # open the HTML report from the last run
```

## How the Zoho mock works

Both lead-capture endpoints — `/api/zoho-proxy.php` (contact form) and `/api/zoho-email-proxy.php` (email popup) — are intercepted via [`tests/fixtures/zoho-mock.ts`](fixtures/zoho-mock.ts). Tests pick `success`, `server-error`, or `network-error` modes. Real network calls to Zoho never happen.

## Adding tests

1. Add a row in `scripts/build-test-cases-xlsx.mjs`, regenerate the workbook.
2. Add the spec in the matching `tests/<group>/` folder.
3. Reference the new Test ID in the spec's top comment (`// Covers: TC-XYZ-001`).
4. Run `npm test` and confirm green.

## Known gotchas

- The dev server lazy-fetches `content/*/content.json` for nav, footer, and resources. Some assertions wait for `networkidle` to let those resolve.
- Email popup uses `localStorage` for cooldown. `tests/interactions/email-popup.spec.ts` clears it in `beforeEach`.
- The contact form's submit listener calls `alert()` on failure — `page.on('dialog', ...)` auto-accepts it.
- WebKit clipboard permissions differ — the copy-email test skips on WebKit.
